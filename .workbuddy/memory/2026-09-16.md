## 修复：自定义高亮规则把中文关键字钻进更长的中文词（「控制距离」里的「距离」被单独上色）

- 现象（老板报）：`也执行动作:控制距离, 撤退` 里的「距离」被异常渲染。
- 根因：`HighlightRuleManager.keywordToRegexPiece` 用 **ASCII 边界**
  `(?<![A-Za-z0-9_])tok(?![A-Za-z0-9_])`。而引擎（joni 2.2.7 + jcodings）按 **Unicode** 判词字符，
  **汉字也是词字符**（实测 `\b距离\b` 不命中「控制距离」，`\w+` 匹配不到纯中文）。
  ASCII 边界只拦 A-Za-z0-9_，等于把规则放宽 → 中文关键字钻进更长的中文词。
- 修复：改回 `\b`（与内置语法完全一致），首尾字符不是词字符（`:`、`#`、`@`…）时不加 `\b`，
  避免语义反转成「后面必须紧跟词字符」。
- 验证方法（可复用）：本地用 **joni jar + 项目 `app/libs/jcodings-1.0.63-noreader.jar` +
  自写 JVM 版 `org.jcodings.util.ArrayReader`（读 `app/src/main/assets/tables/*.bin`）** 跑真实正则，
  对比「内置 `\b(a|b)\b` / 改前 ASCII / 改后 `\b`」三组命中区间。
  结果：改前 6 条样本不一致，改后 0 条。
  - 坑：noreader jar 缺 `ArrayReader`（App 里由 `app/src/main/java/org/jcodings/util/ArrayReader.java`
    影子实现 + `ArrayReader.init(context)` 从 assets 加载），本地跑必须补一个，否则 `\b` 一遇中文就
    `NoClassDefFoundError`。
  - 坑：JVM `java.util.regex` 的 `\b` 默认 ASCII，写 Kotlin 单测要加 `(?U)` 才是 Unicode 口径。
- 改文件：`core/HighlightRuleManager.kt`（keywordToRegexPiece + 注释）、
  `app/src/test/.../HighlightRuleManagerTest.kt`（原 `keywordUsesAsciiBoundariesNotUnicodeWordBoundary`
  断言的是错的，改为 `keywordUsesWordBoundaryLikeBuiltinGrammar` + `keywordPieceNeverAddsCaptureGroup`）、
  `AGENTS.md` §四-9 边界约定。单测 `testDebugUnitTest --tests "*HighlightRuleManagerTest*"` 通过。
- 不需要 bump `DEFAULTS_VERSION`：规则文件内容没变，只改「规则 → 正则」的生成方式，合并语法每次启动重建。

### 核验后确认的高严重度缺陷

1. **自定义高亮开关 = 假回退（最要命）**：`SoraCodeEditor.buildIniLanguage()` 在无生效规则/开关关闭时
   把 `null` 传给 `TextMateLanguage.create("source.ini", null, false)`。**反编译 `language-textmate-0.24.6.aar`
   确认该重载不做 null 判断**，透传到 4 参重载后直接 `registry.findGrammar(...)` → **NPE** → 被 catch 吞掉
   → 返回 null → 编辑器**完全没有语言/高亮**（日志 `No TextMate language set; highlighting will be disabled`）；
   另一条路径 `?: return@LaunchedEffect` 则**保留旧语言 → 开关关不掉**。
