## 智能断行：逗号换行被运算符抢走 → 修（03:05–04:25）

**老板追问**：「资源名(,(换行处)资源名=)换行呢？哪里去了？」→ 回退后逗号处换行看不见了。

**根因（量化，`.workbuddy/tmp/wrap_revert.py`）**：回退版里逗号是**最低档**（`括号组 > and/or > 运算符 > 逗号`），而 `breakLine` 是逐档试、一命中即停 → **行内有任一运算符放得下就轮不到逗号**。老板样例：括号外逗号后位置 = 76/204 单位，运算符 = 88/142；行宽 60/46/40 时运算符(88,段宽70)放不下→逗号档命中（所以之前验证"看得到"），**行宽 ≥ 70 时运算符放得下→抢先→逗号换行消失**（他的行宽正是这种）。

**修法（只动次序，不动结构）**：括号外逗号（depth==0）提到运算符之前 → `括号组 > and/or > 括号外逗号 > 运算符 > 括号内逗号`。括号内逗号（参数分隔）保持最低，避免 `自身资源.敌人/自身资源.队友, 1` 断在逗号后而非 `/` 前。
- `SmartWrapBreaks.kt`：`PriorityBreaks.commas` 拆成 `outerCommas`(depth0) + `innerCommas`(depth>0)，新增 `depth` 数组；`computePreferredBreaks` 同步；`computeFallbackBreaks` 不变（逗号后置 + `sortedSetOf` 保序）。
- `SmartWordwrapLayout.java`：多取两档，选择链里插入 `outerCommas`，新增 `oci`/`ici` 两个推进指针。
- 测试：`priorityBreaksGroupedByPriority` 改用 `outerCommas`；新增 `outerCommaOutranksOperatorWhileInnerCommaDoesNot`。

**效果**（`.workbuddy/tmp/wrap_new.py`，行宽 100）：旧版第 3 行断在 `/`(142) → `...), 队伍=max(自身资源.敌人`；新版断在逗号(128) → `...), ` + `队伍=max(...)` ✓ 行宽 ≤76 两者一致。

**代价**：逗号位置必然比其后的运算符靠前 → 该行留白增大（15→37 单位）。这是"资源名处换行"的固有取舍，已如实写进报告。

**验证**：17/17 通过；`assembleDebug` + `installDebug` 成功（V2505A）。

**坑**：`commaAfter` 返回「逗号后第一个非空白字符」下标，写断言时容易漏算空格（`A=(x), B=(y+z)` 是 7 不是 6）——首轮单测就抓到。
