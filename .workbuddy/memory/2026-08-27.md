## 编辑器「缓存工作区」重构代码审查

用户把编辑器切换从「销毁重载 + 后期光标校正」改为「缓存工作区」，口头描述为「多实例（每个文件一个存活 EditorScreen）」。审查结论：

- **实际仍是单活跃实例 + 数据缓冲，不是多实例**。`MainApp.kt:832` 用 `key(activePath)` 只渲染一个 EditorScreen，切文件整树销毁重建（sora View 也重建），真正存活的只是 `EditorWorkspaceEntry`（text+cursor+scroll 缓冲）。

- 主要风险：`workspace` 用 `remember`（非 rememberSaveable）且 MainActivity 无 configChanges → 旋转/进程重建丢未保存缓冲；`LaunchedEffect(activePath)` MRU 与 onDispose 写回存在时序依赖；落盘用 displayText 反向翻译、englishText/chineseText 缓冲滞后；eviction 保存是 fire-and-forget。
- **更正**：之前说的「灯泡点亮后立刻切走会存错」不成立——`applyLightbulbToggle`（SoraCodeEditor.kt:259-264）是先 `onLitLinesChange` 同步记账、再 `onLightbulbToggle` 改文字，同步无时序窗口。
- **真正的灯泡 bug**：点亮行后切走再切回，取消点亮时英文原文还原不回来。原因：`buildWorkspaceEntry()`（EditorScreen.kt:410）只把 `litLines` 写进 `EditorWorkspaceEntry`，没把 `lineOriginalTexts`（点亮前原文）带上；切走销毁后 `lineOriginalTexts`（remember(filePath)）清空，切回只恢复 litLines，取消点亮（EditorScreen.kt:1162-1169）读不到原文 → 该行卡在中文。修复方向：`EditorWorkspaceEntry` 增加 lineOriginalTexts 字段并随 workspaceEntry 恢复。

- 「任意保存会带动全部文件」确认：`saveSync` 成功分支（EditorScreen.kt:600-602）调用 `onSaveAllWorkspace` → `saveAllWorkspaceFiles`（MainApp.kt:228-237），遍历 workspace 中所有 `isModified` 条目一起落盘。**漏洞**：这个「一起保存」依赖「当前文件先有一次成功 saveSync」带动；若当前文件 isModified=false（如 ON_PAUSE 自动保存的前置条件不满足），saveSync 不触发，其它文件的改动就不会落盘 → 切后台/转屏时其它文件修改裸奔。
