结论要点（后续若跟进此功能直接看这里）：

- 意图：给异形单位加「悬崖地形移速 -80%」+ 对应 UI 条目 `action_悬崖减速显示`。
- 实现方式：`[hiddenAction_移速合成]` 的 setUnitStats 加外层括号后 `* select(self.isOverClift(), 0.2, 1)`。
  - 外层括号是必须的：原式 `A*(1+升级)*(1+效果)+加法+额外`，不加括号只会乘到最后一项。
- 已确认 `self.isOverClift()` 是合法 API（代码参考库/translation.txt 均有，等同 `isOverCliff()`），不是拼写错误。

发现的两个真问题：

1. `模板/异形/近战.template` 里节头写成 `[[action_悬崖减速显示]`（双左括号）→ 解析出的节名为 `[action_悬崖减速显示`，整段属性失效。
   建议：改成单 `[`，并**删掉 `异形自爆.ini` 里同名的那份**（ini 已 `copyFrom:近战.template`，模板那份才是"所有单位都有"的正确位置，两处都留会重复定义）。
2. 悬崖减速会被蜂巢过载状态绕过：`[hiddenAction_进入爆发]` / `[hiddenAction_爆发持续]` / `[hiddenAction_进入虚弱]` 用的是
   `memory.原始移速`，而它在进入爆发时取的是 `${movement.moveSpeed}`（ini 静态基础值），不是合成后的当前移速。
   结果：爆发/虚弱期间 moveSpeed 被写成基础值，悬崖 -80%、脉络 +30%、升级移速全部丢失。
   → 这是既有设计问题，悬崖功能把它暴露得更明显。修法需老板定（原始移速应快照当前实际移速，或各状态分支都乘悬崖系数）。

## 排查：「保存时『真』偶尔没转成 true」

根因（实测确认，未改代码，等老板点头）：

- `真/假` 只在**值表**（valueTranslations），不在中→英通用词表 → 只有两条窄路能翻：
  ① 整个值恰好等于「真/假」（精确匹配）；② 嵌在表达式里时靠 `ZH_BOOL_TOKEN_REGEX`
     `(?<=[=,\(])\s*(真|假)\s*(?=[,\)\}])` 补刀。
- 只要「真」不在「= , ( 之后 + , ) } 之前」这个白名单位置，就原样落盘：
  `if 真` / `not 真` / `真 and 假` / `真 且 假` / `%{真}` / `[真]` / `{真}` /
  `真;假` / `真|假` / `真/假` / `真-假` / `真=>1` / `真<1` / 全角 `真，假` / `真（假）` /
  `(需要=真) and 假`（括号内翻、括号外漏）/ 值尾带零宽字符（trim 不掉，精确匹配失效）。
- 已排除「字典重建窗口」：清空字典后连 key 都翻不了，与老板"只漏真"的现象不符。
- 修法（建议，低风险）：两个布尔 token 正则的边界从"标点白名单"换成"token 边界"
  （前后不是汉字/字母/数字/下划线），并同步 EN 方向；精确匹配前 strip 不可见字符。
  翻译引擎属禁区 → 先报不改。
- 完整报告（原因+修复方案+验证清单，老板要求只查不改）：已合并进下方二次核查后的规范报告，旧文件名作废。
  改的时候两个方向（中→英/英→中）必须一起改，并补 `TranslationBoolTokenTest`。
- **追加实锤（v2，老板给了前后差异）**：真凶是**反译方向把英文值翻成中文**，不是中文翻不回去。
  `translateSingleValue` 的 specialValues 分支（TranslationEngine.kt 581-584）不分方向：
  中→英时 `getValueTranslationBack("true")` → `lookupZhValue` 查 `valueTranslations["true"]`（双向存储）→ 返回「真」。
  实测：`true`→真、`false`→假、`LAND`→陆地、`LAND,WATER,HOVER`→`陆地, 水面, 两栖`；
  大写 `TRUE`、`select(true,1,0)`、`%{true}` 侥幸没事。触发条件 = 中文视图里存在英文形态的值（粘贴 / 英文输入法）。
  修法一行：`return if (enToZh) getValueTranslationBack(processed) else processed`。
  两个缺陷方向相反、互不覆盖，都要修。老板文件里 `[[action_悬崖减速显示]` 是双左括号（节名错），顺手提醒过。
- **二次核查（端到端跑通，结论坐实）**：
  - 值表英文 key 恰好 9 个（true/false/LAND/WATER/HOVER/AIR/OVER_CLIFF/OVER_CLIFF_WATER/NONE），全部 ∈ specialValues
    → 第 581 行是唯一出口，改一行足够；587 行分支对这些值不可达（实测普通英文值 infoOnlyNoBox/0s/ROOT: 均原样）。
  - `AUTO`、`TRUE`/`False` 侥幸没事（值表没登记 / 只登记小写）。
  - **更正**：上一版说「取消行尾灯泡会触发」是错的 —— 熄灭恢复的是 `lineOriginalTexts`（点亮前的中文视图行），不是英文。
    真正引入英文的路径：粘贴、英文输入法、`getChineseContent` 两个兜底返回英文原文（`awaitReady` 失败 / `translateToChinese` 异常，
    此时仍按 isEnglish+showChinese 处理，保存即整篇反译）、外部文本替换。
  - 规范修复报告：`docs/修复报告-布尔与枚举值被反译成中文-2026-10-23.md`（旧版排查稿已删，避免两份并存）。
