## 一、🟡 真实遗留的问题（4 条）

### 1. 「类别承诺了、语法里没有」的空范围，共 18 处

类别表里每个类型都声明了自己管哪些范围，其中有 **18 处在语法文件里根本不存在**（逐个数出来的）：

**三个整类空转**（声明的范围全部 0 处）：

| 类别 | 声明管什么 | 实际 |
|---|---|---|
| 属性/常量 | 4 个范围 | 全部不存在 |
| 字符串引号 | 2 个范围 | 全部不存在（引号实际由「字符串」带色） |
| 修饰符 | 1 个范围 | 不存在 |

**六个活类别里混着死范围**：

| 类别 | 死范围 | 活范围 |
|---|---|---|
| 属性值 | 正斜杠分隔 | 值词表、冒号 ✅ |
| 字符串 | 多行字符串 | 单/双引号 ✅ |
| **移动类型** | 4 个死了 3 个（移动/层级/动画），只活 1 个 | 大写移动类型 ✅ |
| 内存/变量 | 3 个死了 2 个 | @memory 声明关键字 ✅ |
| 节前缀 | 1 个 | 节名 + 节括号 ✅ |
| 注释 | 块注释、注释标记 | 行注释 ✅ |

这 18 处**不影响现有颜色**（类别里有活的就够），但它们是"类别承诺了却管不到"的空头支票；主题文件里还留着 25 条对应的死配色。看起来是语法精简时没同步清理的遗留。（另一会话的日志里登记过"只登记不动"—— 本报告把它们汇总成完整清单。）

### 2. 「自身检测」组名装不下组里的词

这个组现在 43 个词，其中 **7 个跟"自身"没关系**：

- `有全局标签`（查的是全局，不是自身）
- `队伍获胜`、`队伍失败`、`队伍无单位`（查的是队伍）
- `核武启用`、`正在游戏的地图高度`、`正在游戏的地图宽度`（查的是游戏全局）

颜色不受影响（它们和"自身检测"同属「属性值」类别、同色），但你在「自定义高亮 → 规则」里按组找词时，会在"自身检测"里看到"核武启用"，观感就是"分组错了"。

### 3. 「自身检测（英文）」组名同样装不下

46 个英文词里有 `mapWidth`、`numberOfUnitsInTeam`、`hasResources` 这类，不全是"检测自身"。与第 2 条同性质：组名偏窄。

### 4. 「属性」和「属性/常量」撞名

「属性」管的是每行开头的**键名**（`隐藏血量:` 左边那截）；「属性/常量」是第 1 条里说的那个整类空转的死类别。规则页里两个都带"属性"二字，不可能分清哪个管什么。

## 二、🟢 备查（2 条，都有解释、不算错）

**5. 「属性值」类别里含"冒号"** —— 冒号（`键:值` 的分隔符）在主题里跟值同色，所以归进「属性值」。对照表文档里已说明过，理解成本不高，但严格说类别不纯。

**6. 「内存类型」这个名字** —— 它管的其实是数据类型（`float/number/boolean/unit/string`），叫"内存类型"是因为真实项目里这些词只在 `@memory 声明:float[]` 的类型位出现。这是你逐条定的 7 个命名之一，已确认过，仅备查。
