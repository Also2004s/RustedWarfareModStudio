# 最小改动清单（2026-09-16）

标准（老板定的）：**只改没有任何隐患的、最小改动、只改只会有正面影响的。**

---

## 一、筛选结果：13 项里只有 **3 项**合格

| 结果 | 数量 |
|---|---|
| ✅ 合格（零隐患、纯正面、改动极小） | **3 项**（+1 项可选） |
| ⏸ 推迟（都有隐患，不符合标准） | 10 项 |

**筛掉的 10 项不是因为不重要，是因为它们全都涉及下面任意一项**：
改线程 / 动用户数据 / 改界面行为 / 依赖未知的外部反应 —— 只要沾上一条，就**不能保证"只有正面影响"**。

## 二、要做的 3 项

### ✅ 1. 项目说明书的事实性修正（纯文档）

**改什么**（3 处，都已核实是事实错误）：

| 位置 | 现在写的 | 实际是 |
|---|---|---|
| 版本号 | `versionCode = 27`、`versionName = "1.3.6"` | **30**、**"1.5.0"** |
| 页面清单（§三 目录结构下方） | 列了 14 个页面 | 实际 **16 个**，缺 `MOD_INFO`、`RECYCLE_BIN` |
| §四-9 自定义高亮 | "无启用规则时返回 null（调用方回退到单例注册表，**等于零改动**）" | **与实际相反**：实际会崩溃、编辑器**完全没有高亮** |

**为什么零隐患**：改的是说明文档，不影响任何运行行为。

**注意第 3 处怎么改**：**不能**把它改成"关开关会正确回退"——因为**代码还没修**，那样改文档反而变成新的错误。
正确做法：**如实标注为已知缺陷**，并指向审计报告（`docs/bug-audit-2026-09-16.md`）。这样文档与代码现状一致，消除误导。

**验证**：打开文档核对这 3 处。

### ✅ 2. 删掉一个用不上的外部库

**改什么**：从依赖清单里删掉 `navigation-compose`（`app/build.gradle.kts:114`）。

**为什么零隐患**：已核实**全项目没有任何一处引用它**（导航是手写的）。
更关键的是：**这类改动如果删错，会在编译阶段就报错，不会藏到运行期**。最坏结果也只是"编译不过 → 加回来"，**不会让 App 出问题**。

**正面影响**：包体变小、少背一个没人用的东西。

**验证**：删完**完整出一遍包**，能正常启动、几个主要页面能来回切换。

---

### ✅ 3. 文件浏览器里"同一个值算两遍"合并成一遍

**改什么**：`FileBrowserScreen.kt:696-697`

```kotlin
// 现在：同一个值，连着算两次
if (BookmarkManager.isBookmarked(file.absolutePath)) 图标A else 图标B,
if (BookmarkManager.isBookmarked(file.absolutePath)) "取消书签" else "书签",

// 改成：算一次，用两次
val 已收藏 = BookmarkManager.isBookmarked(file.absolutePath)
```

**为什么零隐患**：
- 两次调用之间**没有任何状态变化**，所以两次结果**必然相同**，合并后结果完全一致；
- 只是把它从"算两遍"变成"算一遍"；**不改任何判断逻辑、不改界面**。

**正面影响**：每打开一次长按菜单**少一次读盘**（这个判断会读收藏文件、还逐条检查文件是否存在）。

**验证**：长按一个 ini 文件 → 菜单里"书签/取消书签"的文字和图标**和以前一样**，点了能正常加/取消。

### ⭕ 4.（可选，价值低）清掉一个永远成立的条件

**改什么**：`MainApp.kt:838`、`:1224` 里的 `(bookmarkTick >= 0) &&`。
这个条件**永远为真**（计数从 0 开始，不会变成负数），写了等于没写。

**为什么零隐患**：删掉一个恒为真的条件，结果不变。

**要不要做**：纯代码整洁，**对用户没有任何影响**。你说做就做，不做也不影响。

## 三、推迟的 10 项（都有隐患，逐项说明）

| # | 项 | 为什么不符合"零隐患"标准 |
|---|---|---|
| 1 | 高亮开关 | 要改"语法装载 + 颜色编号 + 影响其它 4 个后台实例"，还牵扯用户规则校验，**改法复杂、副作用面大** |
| 2 | 打开文件卡 | 要动线程；文本是靠 **(内容, 序号) 配对**推给编辑器的，**插错位置会显示错误内容** |
| 3 | AI 报告 | 要换网络为流式 + 节流 + 收尾 + 降级，**还跟另外 3 个 AI 功能共用接口** |
| 4 | 书签缓存 | 加缓存后**已删除文件的书签不会自动消失**（会出现"幽灵书签"） |
| 5 | 最近列表 | 要改判断逻辑；字符串比较**替不掉真实地址解析**；列表有重复项还会崩 |
| 6 | 首页/搜索页 | 改异步后**首帧会空一下**，看起来像闪 |
| 7 | 查重 | 要动线程；不节流**反而会卡** |
| 8 | 内存上限 | **一生效就让"预热"白做 → 搜索变慢**；而且**上线值要看你项目的数据量** |
| 9 | 规则保存 | 要改写入方式；有 **8 个写入入口**，光换写法**防不住"连点丢规则"** |
| 10 | 升级设置回读 | 动的是**用户数据**；**回读会冲掉用户本会话刚改的设置** |
| 11 | 弹窗统一 | 约 **45 处**；**宽度和按钮排布会不会变必须实测**，改坏了用户直接看得见 |

> 这些都在 `docs/修复回归风险核查-2026-09-16.md` 里逐条写了规避办法。
> **等你想做哪一项，单独拿出来批，不要一次全上。**

## 四、本轮的三条保证

1. **不碰翻译引擎（禁区）** —— 本清单 3 项全在禁区之外。
2. **不动任何用户数据** —— 不碰设置文件、翻译库、补全表、历史、待办。
3. **不改任何行为逻辑** —— 3 项里 1 项是文档、1 项是删无用依赖、1 项是"算两遍改算一遍"，**运行结果完全一致**。

另外：本轮**不需要**改任何"强制刷新码"，也**不需要**改版本号（不发布）。
