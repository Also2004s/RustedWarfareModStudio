## 二、逐项详述

### 1. [P0] 同一文件并发写盘无全局锁 —— 数据损坏

**现象**：`File.atomicWriteText` 使用**固定临时文件名 `$name.tmp`**。两个及以上协程并发写同一路径时，会同时截断/写入同一个 tmp 文件，可能拼出**混合内容**后 rename 落盘，目标文件内容损坏。

**触发路径**（App 退后台时最集中）：
- `EditorScreen.kt` L1196-1230：每个实例都注册 `LifecycleEventObserver`，ON_PAUSE 时最多 5 个实例同时触发 `saveSync` / `onSaveAllWorkspace`。
- `saveSync` 有 per-instance `saveMutex`（L602），但宿主侧 `saveWorkspaceEntry`（MainApp L212-244）、`saveAllWorkspaceFiles`（L248-257）、`onDisposeFlush`（L946-957）**无锁**。
- `flushInactiveInstances`（L261-265）只改 `openPaths` 移实例，落盘依赖实例 onDispose 回调 → 同一文件最多 3 路并发 `atomicWriteText`。

**修复**：`AtomicWrite.kt` 加 JVM 级 `WRITE_LOCK` + `synchronized`，串行化「写 tmp → rename」整段。`atomicWriteText` 是全项目唯一写盘漏斗（saveSync / saveWorkspaceEntry / revertFile / 搜索替换 / HomeScreen 均汇聚于此），一处加锁覆盖所有入口与未来新增调用。写盘低频小文本，串行化开销可忽略。

### 2. [P0] 陈旧 workspace 条目覆盖新内容 —— 丢改动

**现象**：`flushInactiveInstances` 只清 `openPaths`，不同步刷新 workspace 条目；`saveAllWorkspaceFiles` 遍历 workspace 中 `isModified` 条目落盘。

**复现路径**（autosave 关闭 + holdPaths 暂存场景）：
1. 文件 X 的实例销毁时缓存 `isModified=true` 条目（暂存路径只缓存不落盘）→ workspace[X] 是旧快照 v1。
2. 重新打开 X 编辑出新内容 v2，但 workspace[X] 仍是 v1。
3. 从文件 Y 点保存 → `saveAllWorkspaceFiles` 把陈旧的 v1 写盘 → `flushInactiveInstances` 销毁 X → `onDisposeFlush` 写 v2。
4. 两协程顺序不保证，**v1 可能后到覆盖 v2** → 磁盘留下旧内容。

**修复**：`saveAllWorkspaceFiles` 跳过 `openPaths` 中**有存活实例**的路径——存活实例的内容由自身 saveSync/onDisposeFlush 从实时编辑器文本写盘，workspace 缓存只对「无存活实例」的文件才是权威。被跳过的 live 路径由 onDisposeFlush 兜底。

### 3. [P0] IO 线程写 Compose state —— 确定性 bug

**现象**：`saveSync` 在 `withContext(Dispatchers.IO)` 块内（L658）调 `onSaveAllWorkspace?.invoke()` → MainApp L960 `flushInactiveInstances()` 执行 `openPaths = listOf(current)`（L264），**跨线程写 Compose state**，违反 Compose 单线程模型，debug 下可能抛异常、release 下状态错乱。

**修复**：`onSaveAllWorkspace?.invoke()` 移入已有的 `withContext(Dispatchers.Main)` 块（L649-666）末尾。移后 `saveAllWorkspaceFiles` 在 Main 读 workspace 快照、内部写盘经自身 `withContext(IO)` 挂起跳转、state 更新回 Main；`flushInactiveInstances` 的 `openPaths` 写在 Main——全链路无跨线程 state 访问。语义不变：仍在 saveMutex 内、try 内、stillUnchanged/isModified/onSaved/onWorkspaceCache 顺序不变。ON_PAUSE else 分支（L1211）本就在 lifecycleScope(main)，无需改。

### 4. [P1] SaveHistoryManager 非原子写 + 历史链断裂

**现象**：
- `save()`（L173-191）用 `file.writeText` 直接截断写 `save_history.json`，进程被杀/磁盘满时文件损坏。
- 并发写盘时同文件双读旧 beforeContent → 记录重复/断裂历史链（before 均读旧值）。

**修复**：
- `save()` → `file.atomicWriteText(...)`（一行）。
- `record()` 加去重：同文件连续 record 且 beforeContent 相同（并发双读旧值标志，合法链中连续 before 必不同）则跳过。

### 5. [P1] 保存无父目录校验

**现象**：`saveSync`（EditorScreen L623）与 `saveWorkspaceEntry`（MainApp L222）对目标路径无父目录存在校验，目录被删时 `tmp.writeText` 抛 IOException 被笼统 catch 成「保存失败」，原因不明。

**修复**：两处均在写盘前加父目录校验，缺失则提前返回失败（不自动 mkdirs，保持「文件应存在」语义）。

### 6. [P2] onDisposeFlush fire-and-forget（残留）

`MainApp.kt` L955 `scope.launch { saveWorkspaceEntry(entry) }` 不 await，进程被强杀（后台回收/强停）时最后修改可能丢失。ON_PAUSE 已覆盖绝大多数退后台场景（自动保存开启时），残留窗口仅剩极端 kill 场景。编辑器类应用可接受；彻底解决需 WorkManager/前台回调，超出本次范围。

## 五、残留风险（评估：可接受）

1. onDisposeFlush fire-and-forget，进程强杀丢最后修改（见 #6）。

3. 历史去重极端并发下少记中间瞬态，磁盘最终内容正确。
