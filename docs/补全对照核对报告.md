## 二、本次发现并已修复的问题

### 1. `if` 之后给不出布尔函数（已修复）
- **场景**：项目高频 `需要条件:if 自身有标签(...)`、`自动触发:if 存活时间(...)` —— `if` 后紧跟**布尔函数**。
- **原 bug**：`LogicBooleanValueCompletionProvider.isBooleanEntry` 条件含 `booleanPrimitives.any { it.startsWith(filterPrefix) }`，当 `filterPrefix="if"` 时命中，Provider 只给 `真/假/if`；同时主流程 `valueEndsWithLogicKeyword("需要条件:if ")` = true 又把这些全部过滤 → **`if` 后补全为空，布尔函数给不出来**。
- **修复**：`isBooleanEntry` 仅在 `filterPrefix.isEmpty()`（真正空值，如 `自动触发:` 后）触发，输入 `if` 前缀即进入表达式模式给布尔函数。
- **修复后**：
  - `自动触发:`（空值）→ `真/假/if` ✅（项目 `自动触发:真`）
  - `需要条件:if ` → 布尔函数 ✅（项目 `需要条件:if 自身有标签`）
  - `自动触发:if ` → 布尔函数 ✅（项目 `自动触发:if 存活时间`）

### 2. `min/max` 等函数参数位置类型过宽（已修复）
- **场景**：项目 `min(1+max(int(...),0), 8)`、`平方根(自身资源.AI难度*...)` 参数全是**数值**。
- **原 bug**：`LogicExpressionContext.buildSignature` 未识别 `num1`/`num2`/`num`/`start`/`end`/`unit1`/`unit2` 等参数名，全部归 `ANY` → 参数位置不过滤，误给 `真/假`/字符串 等。
- **修复**：`min/max(num1,num2)`、`squareRoot(num)`、`substring(text,start,end)` 参数归 `NUMERIC`；`distanceBetween(unit1,unit2)` 归 `UNIT_MARKER`。
- **边界**：`select(bool,textA,textB)` 的 textA/textB 保持 `ANY`（项目填数值/字符串/真/假都有，正确）。
