# 值补全的「跟着场景定语言」修正（2026-09-17）

> 起因：老板指出「自身在地块类型上(type= 这块自动补全出的地块类型（如 LAND）好像不会被翻译，用英文就可以了；
> 但运动类型: 里的 LAND 是会被翻译成陆地的」，要求按场景判断补全词会不会被翻译。

---

## 一、为什么会有这个差别（大白话）

翻译库里有两类词，规矩不一样：

1. **整值专用词**——`LAND / WATER / AIR / HOVER / OVER_CLIFF / OVER_CLIFF_WATER / NONE / AUTO`。
   这类词只有在**整行「冒号后面就是它一个」**的时候才会被翻译，比如 `运动类型: LAND` 显示成「陆地」。
2. **普通词条**——比如 `move`（移动）、`own`（己方）、`building`（建筑）。这类词在句子里出现也能翻。

关键在于：**一旦这些词夹在括号参数里（`type=LAND` 这种位置），引擎既不会翻它，反着翻译也认不出它。**
也就是说，括号里写 `LAND`，中文视图里还是 `LAND`（这跟老板看到的一致）；而括号里写 `陆地`，保存时**永远变不回 `LAND`**，
文件里就留下一个游戏看不懂的值。

补全弹窗之前没区分场景，在括号里给的也是中文 → 用户点一下，插进文件的就是中文 → 保存后地雷就埋下了。

---

## 二、修之前 / 修之后

### 🔴 括号里的「地块类型」补全插的是中文，保存后文件里就是中文

- **你遇到的情况**：在 `自身在地块类型上(type=` 后面调补全，弹出的是「陆地 / 建筑 / 空中 / 水面 / 悬停 / 跨悬崖…」，
  选中后写进文件的是 `type='陆地'`。中文视图下保存，这一处**不会被还原成英文**，文件里就留着中文值，
  铁锈读不懂这个参数。
- **为什么会这样**：补全只看了「翻译库里有没有这个中文」，没看「这个位置上引擎到不到得了这个中文」。
- **修好后**：这一处补全恢复英文值（`LAND / AIR / WATER / HOVER / OVER_CLIFF…`），
  中文含义改在右侧副标题里说明（`LAND — 陆地`）。插入的永远是英文，文件怎么保存都不会错。

### 🟡 同一个参数列表里中英混排

- **你遇到的情况**：`type=` 弹出的一串里，7 个是中文，中间夹一个英文 `BUILDING`（它没被翻译库收录）。
  一半中文一半英文，看着不像同一组东西。
- **修好后**：**同一批值要么整批中文、要么整批英文**。地块类型这批带「整值专用词」，所以整批走英文，不再混排。

### 🟢 `运动类型: LAND` 这类不受影响

- 这里是「整值位置」，引擎会翻成「陆地」，保存时也能还原回 `LAND`，属于你说的正常情况，**没动它**。

### 全场景一览（判断尺子）

| 场景 | 引擎在这个位置的行为 | 补全给什么 | 本次是否改动 |
|---|---|---|---|
| 属性整值：`运动类型: LAND` | 会翻成「陆地」，反译也能还原 | 中文 | 不动 |
| 括号参数（整值专用词）：`type=LAND` | 不翻，反译也认不回 | **英文（+副标题中文说明）** | ✅ 本次改 |
| 括号参数（普通词条）：`type=move`、阵营 `own/ally` | 双向都翻得动 | 中文 | 不动 |
| 括号参数布尔：`…=true` | 引擎对真假有句中补救 | 中文可以 | 不动 |

## 五、追加：那个开关开着的时候怎么办（老板提的「分两种情况算」）

### 为什么得管
屏蔽词里有个开关「引号内的词不翻译」。它一打开，引号里的内容引擎就整段绕着走——**不翻成中文，也不还原成英文**。
而参数值补全里有一批值是**带引号**的写法（`type='unit'`、`relation='ally'` 这种）。那时如果还插中文，中文就会永久留在文件里。

### 分两种情况后的行为（已实现）

| 那个开关 | 带引号的参数值（type / relation / enum） | 说明 |
|---|---|---|
| 关（默认，你平时这样） | 照旧给中文（`type='移动'`） | 不变，显示和保存都对 |
| 开 | **自动改用英文**（`type='move'`），中文含义仍在右侧副标题 | 本次新增 |

- 不带引号的位置——数值、参数名（`超过=`）、资源名（`能量=`）、布尔（`真/假`）——**两种情况都不受影响**，照旧中文。
- 项目自己的名字（标签名、内存名、附属槽名）**不动**：那些名字本来就是你项目里怎么写就怎么写，引号保护恰好是在保护它们。

### 验证
- 新增 4 条单测（开关开/关 × 带引号/不带引号），全过；全量单测 **278 条，0 失败**。

## 附：给开发者看的（老板不用看这段）

**问题链路**
- 补全侧：`FunctionParameterCompletionProvider.provideParamValues` → `translateDictValues(values, dict, param.type in enum/type/relation)`
  → `dict.getValueTranslation(v)`。该 API 查 `valueTranslations` 优先（`TranslationDict.kt:1014`），
  而 `valueTranslations` **只装 specialValues 词**（`TranslationDict.kt:304/455/476/694/808/924` 全由 `en in specialValues` 守卫）
  → `LAND` 拿到「陆地」并作为 label/insertText 插入。
- 引擎侧：句中翻译只用 `enToZh/zhToEn` 预编译正则（`TranslationDict.compilePatterns`，`:951` 注释明确「不包含 valueTranslations」），
  specialValues 只在 `translateSingleValue` 的「整值命中」分支生效（`TranslationEngine.kt:581-590`）。
  ⇒ 括号内 `type=陆地` 正向不显示、反向 `translateInText` 也命中不了 ⇒ 不可逆。

**改法**（`app/src/main/java/com/rwmodstudio/feature/completion/value/FunctionParameterCompletionProvider.kt`）
- 场景闸 `canTranslateValuesInPhrase(values, dict, quoted, quotedProtected)` 两道：
  - 闸1（整值专用词）：`values.any { it in dict.getSpecialValues() }` → 整批英文；
  - 闸2（引号保护）：`quoted && quotedProtected` → 整批英文。
- `translateDictValues(values, dict, translate, quoted = false)` 在「语言总闸」之后过场景闸；
  `quoted` 由调用点按 `param.type in quotedValueParamTypes`（新抽出的唯一来源常量，
  同时作为 `buildParamValueSuggestions` 的 `quoteTypes` 默认值）传入。
- `quotedProtected` 来自新增的 `CompletionShared.quotedValuesBlocked()`
  = `TranslationEngine.getInstance().getBlocklist().let { it.enabled && it.blockQuotedDictWords }`（默认 false）。
  判定用引擎自己的开关状态，非硬编码；引号保护实测：开 → 引号内被替换为 `@@QUOTE_0_@@` 占位（`protectQuotedDictWords`）。
- 只对 enum/type/relation 生效（只有这三个类型会走 `translateDictValues` 且都在 `quoteTypes` 内）；
  `tag/messageTag/actionTag/attachmentSlot/memoryName` 是**项目自定义名**，必须按项目原样保留，
  故意不纳入（引号保护对它们恰恰是保护）。数值/参数名/资源名/布尔不带引号 → 两种情况都不受影响。
- 用 `getSpecialValues()`（引擎自己的常量）而非硬编码名单；插英文对引擎永远是 no-op，零风险。
- 未改翻译引擎、未改 `ValueDataLoader`（属性整值场景照旧翻 name → 中文，安全）、未改字典数据、未 bump 任何验证码
  （补全项条数不变，模拟 ini / 补全类型分类计数不变）。
